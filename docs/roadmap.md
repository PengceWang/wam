# 实现路径

最终目标：**告诉 agent "去砍点树，然后盖个小房子"，它去做** —— 并且这套机制
要能迁移到现实世界。

这份路线图是在读完 VPT / STEVE-1 之后重排的。**已经站住的东西全部保留** ——
下面每一条"地基"都是这个仓库自己测出来的，不是从论文抄的，而且大多是踩坑踩出来的。

## 0. 已经站住的地基（不动）

这些不需要重做，后面每一步都建在上面。

| | 结论 | 证据 |
|---|---|---|
| 上下文长度是**能力下限** | 每 8/16/32 步打断一次，5400 步原木事件全为 0；不打断则 5.00/千步 | `online-rl-log.md` §3 |
| **清 cache ≠ detach cache** | 清会毁能力，detach 只是不回传长程梯度 | 同上 |
| 信用视野与上下文**已解耦** | 优势估计不需要梯度，可以很长而不花显存 | `online.py` |

| 评测要 6000 步 | 900 步评测里 BC 只有 **2 次**事件，四轮结论因此作废 | `online-rl-log.md` §1 |
| 塑形权重按**频率**定 | `0.3×树叶` 对 `1.0×原木` 实际是 100:1，原木归零 | `online-rl-log.md` §2 |

## 1. 从文献拿到的四条修正

| | 我们原来 | 改成 | 依据 |
|---|---|---|---|
| 目标空间 | 冻结 LLM 的 token 嵌入袋 | **视觉嵌入**（`GoalEncoder.from_visual`） | STEVE-1 消融：视觉+prior > 直接文本；与我们自己的测量一致 |
| 重标注粒度 | 150 步整段一个目标 | **15–200 步变长连续区间** | STEVE-1 packed hindsight relabeling |
| 让目标起作用 | 只有 `goal_sensitivity` 指标 | **训练丢弃 p=0.1 + 推理 CFG** | STEVE-1 图 5：挖土 7.5×、砍木 15× |
| 任务结构 | 四个平权任务 | **带梯度的序列**，后段物品给更高分 | VPT：单一稀疏奖励几乎拿不到分 |

### 还有一条关于规模的现实

VPT 的 RL 微调用了 **1.4 × 10¹⁰ 帧**，我们这轮是 **1.5 × 10⁶** —— 差一万倍。
所以"模型是不是太笨"在我们的预算下**根本没被测到过**。

这条不是让我们去堆算力（真机 30fps 跑 1.4e10 帧要 15 年，现实世界里这条路不存在），
而是把目标定死在**样本效率机制**上：后见之明重标注让每一条轨迹都产生训练信号，
哪怕它没完成当时的目标。这才是能带去现实的部分。

## 2. 为什么 RL 必须留着

后见之明只能重标注你**碰巧**达成过的结果，它发明不出新结果。分工是：

* **PPO 负责探索** —— 去做还没做过的事
* **后见之明负责消化** —— 把每条经验都变成训练信号

VPT 的顺序（BC 打底 → RL 微调 → 全程 KL 约束防遗忘）在真机上同样成立，
只是"BC 打底"在现实里会变成遥操作数据。这个顺序不变。

**还有一条现实世界的硬约束，值得单独写下来：** 当前奖励读的是 Minecraft 的
`info["inventory"]` 和事件流。**现实世界没有这个 API。** 所以依赖物品栏增量的
奖励设计本身就是死路，不管写得多干净。视觉目标 + 后见之明恰好去掉这个依赖 ——
目标是"成功时世界看起来什么样"的编码，任何摄像头都能产出。

## 3. 步骤

### 步骤 A —— 验证视觉目标空间（便宜，先做）

不需要训练就能判：把一批轨迹片段用 `from_visual` 编码，看同类行为的片段
是否比不同类的更近。这正是 `from_text` **失败**的那个测试（八个随机向量打平）。

判据：同类/异类的余弦间隔显著 > 0。**不过关就不要往下走** ——
后面每一步都建在"目标空间有语义"这个前提上。

### 步骤 B —— 目标条件化 BC，用现有承包商数据

packed 重标注 + 视觉目标 + 目标丢弃 p=0.1。数据和索引都是现成的。

判据：**CFG 的 λ 从 0 调到 3，砍木/挖土的率是否上升**。
STEVE-1 报的是 7.5× 和 15×；我们不需要复现倍数，只需要方向明确为正。
这一步同时是对整套目标机制的端到端验收。

### 步骤 C —— 在线 RL，接在 B 后面

`train_multitask.py` 的结构不变（PPO 探索 + SIL 消化），
把目标空间换成 B 训好的视觉目标，重标注换成 packed。
KL 约束保留（VPT：没有它 10 万回合后停滞并遗忘）。

判据：**每个任务各自的达成率**，以及 `goal_sensitivity` > 0。

### 步骤 D —— 序列结构的长程任务

到这一步才谈"砍树 → 木板 → 工作台 → 房子"。VPT 式的分级序列奖励，
后段给更高分。在此之前谈长程都是空的。

## 4. 正在跑、结果仍然有用的

两条 BC 消融（这台机器上）：`seq_len 8→32`、骨干 `0.6B→1.7B`，
各自相对 `stage1b_cl` 只改一个变量。它们量的是 BC 的窗口与容量，
和上面的目标机制**正交** —— 无论走哪条路，都需要知道 BC 底座该配多大、窗口该开多长。

特别是 seq_len：砍断一根原木要 7.5 个模型步，而 BC 训练窗口是 8 步，
**几乎装不下一次完整的砍树**。这条如果成立，它会同时解释 BC 为什么弱、
以及为什么 RL 从这个起点出发很吃力。
